# POS 购物车套餐匹配

实现见 `src/utils/comboMatch.ts`。规则与 `product-api` `POST /pos/combs/match` 一致。

## 何时算一套

后台套餐是若干选项组。购物车里每一组都凑够 `requires` 份（从该组 `products` 里扣数量）才算 1 套。剩余数量继续凑，直到凑不齐。

例：套餐 = A1 + B1 + C1，售价 38。购物车 A×2、B×2、C×1 → 1 套 + 剩余 A1、B1。应收 = 38 + A原价 + B原价。

## 价格

- 套餐部分：`套餐售价 × 套数` + 被凑进套餐的规格加价
- 剩余单品：商品本身单价 + 规格加价。套餐槽位价为 0 时仍按商品原价，不按 0 元
- 购物车合计用这套结果；下单 `buckets.Price` 按套餐价分摊到被凑中的商品，保证支付金额一致

## 数据

打开购物车拉取 `POST /v1/hlj/product/pos/combs`，缓存到 `catalogCache`。

x9 套餐菜谱请用「套餐包含产品」勾选 A/B/C 并填套餐售价，保存后重新勾到门店。旧数据若 `combo[].products` 为空，打开菜谱再保存一次即可。
